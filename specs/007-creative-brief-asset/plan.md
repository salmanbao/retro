# Implementation Plan: Creative Brief and Asset Management

**Branch**: `007-creative-brief-asset` | **Date**: 2026-05-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/007-creative-brief-asset/spec.md`

## Summary

Build a Creative Brief and Asset Management module that allows Brand profiles to attach structured creative briefs and asset metadata to campaigns. Editors can access briefs and asset metadata for published/active campaigns. Asset versioning and soft deletion are implemented. Binary storage is excluded.

## Technical Context

**Language/Version**: Go 1.23+

**Primary Dependencies**:
- chi v5 (HTTP router)
- GORM v2 (PostgreSQL ORM)
- Existing middleware (auth, ownership, profile-type)

**Storage**: PostgreSQL with JSONB for flexible arrays (talking_points, hashtags, references)

**Testing**: go test with unit/integration/contract test packages

**Target Platform**: Linux server (Modular Monolith)

**Project Type**: Backend API module (extends existing campaign system)

**Performance Goals**: Standard HTTP API latency (<200ms p95)

**Constraints**: No binary upload handling, no S3/R2 integration

**Scale/Scope**: Per-campaign; ~10 assets per campaign average

## Key Design Decisions

### 1. JSONB for Flexible Arrays
Fields like `key_messages`, `talking_points`, `hashtags` are stored as JSONB. This avoids a separate junction table while allowing PostgreSQL to query within these arrays when needed.

### 2. Version Number as Integer
Version is a simple incrementing integer per (campaign_id, original_filename) group. No separate version history table needed - all versions are rows with different version numbers.

### 3. Soft Deletion Pattern
`deleted_at` timestamp (nullable). Queries exclude soft-deleted rows by default via GORM scope.

### 4. Edit Restrictions Based on Campaign State
Campaign state is checked at service layer. The brief update service accepts the campaign status and returns error for restricted fields.

### 5. Editor Read-Only via Middleware
Editors can GET briefs and assets for published/active campaigns. Brand owners have full CRUD. Profile type middleware enforces this.

## API Endpoints

### Creative Brief

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/campaigns/{campaignId}/brief` | Get campaign's creative brief |
| PUT | `/api/v1/campaigns/{campaignId}/brief` | Create or replace creative brief |

### Asset Metadata

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/v1/campaigns/{campaignId}/assets` | Register new asset |
| GET | `/api/v1/campaigns/{campaignId}/assets` | List campaign assets (paginated) |
| GET | `/api/v1/assets/{id}` | Get single asset details |
| PATCH | `/api/v1/assets/{id}` | Update asset metadata |
| DELETE | `/api/v1/assets/{id}` | Soft-delete asset |
